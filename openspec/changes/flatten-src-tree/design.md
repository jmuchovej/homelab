## Context

See proposal.md for motivation. The facts that shape the approach:

- `flake.nix` is generated by `flake-file` from `src/modules/inputs.nix` (`flake-file.outputs`). The `import-tree ./src/modules` root is the only place the flake knows about `src/`; everything else inside `modules/` uses file-relative paths (`./_lib`, `./_git-hooks/...`, `<rbn/...>` aspect names) and is layout-agnostic.
- Four modules build absolute paths from `inputs.self`: `services/kubernetes/kubernetes.nix` (`src/bootstrap/kubernetes`, `src/topology.yaml`), `services/zerotier.nix` (`src/topology.yaml`, twice), `system/virtualization/talos.nix` (`src/bootstrap/talos/machineconfig.yaml`), `system/nix-builders.nix` (`src/modules/hosts/<host>/facter.json`).
- `src/bootstrap/` is untracked and only `talos/machineconfig.yaml` exists on disk in the main checkout. `kubernetes.nix` reads `cilium.yaml`, `cilium-values.yaml`, `flux-instance.yaml`, `flux-operator.yaml`, `flux-agekey.yaml`, and `checks.nix` from `src/bootstrap/kubernetes/`, which does not exist in any workspace. Hosts `en-t65-1` and `da-vcx-1` include `<rbn/services/kubernetes/server>`, so those evaluations cannot currently succeed. This is pre-existing and orthogonal, but it means the "before" baseline for the Nix gate is whatever evaluates today, not a full `nix flake check`.
- Each cluster's `FluxInstance` carries `spec.sync.path`, the directory in the cloned repo that flux-operator treats as the entrypoint. Flux-operator turns it into a `GitRepository` (the whole repo, one artifact per commit) plus a root `Kustomization` named `flux-system` that applies only that directory. Per `src/kubernetes/AGENTS.md` the path is `src/kubernetes/clusters/<dc-domain>/flux`, holding exactly `cluster-config.ks.yaml` and `cluster-apps.ks.yaml`. The value lives in cluster state; its source, `bootstrap/kubernetes/flux-instance.yaml`, is work in progress and not yet in the repo, so the live value must be read from the cluster rather than inferred.
- All 59 Flux `Kustomization` objects use `path: ./src/kubernetes/...`; kustomize `resources:` entries are relative and unaffected.
- `src/terraform/` uses `${path.root}/secrets/...` and `${path.root}/topology.yaml` through two symlinks: `secrets` points two directories up to the repo-root `secrets/`, and `topology.yaml` points one directory up to `src/topology.yaml`. Local state (`terraform.tfstate` and three backups, ~5 MB), `.terraform/`, `authentik.auto.tfvars.json`, and `.scratch/` are gitignored and live in the main checkout only. `da.cloudflare-tunnel.tofu` is untracked but not ignored there.
- Root `justfile` loads three modules by path. `just` 1.58 runs module recipes with the module file's directory as cwd, so `authentik.just`'s `secrets := "secrets/secrets.sops.yaml"` resolves through the `secrets` symlink, and its `sync-outpost-tokens` recipe reads `secrets/authentik.sops.yaml` one directory up, which only lands on the repo root once the module sits one level below root. The existing `[working-directory("mikrotik/")]` on the root `topology` recipe already assumes a root-level `mikrotik/`.
- `.sops.yaml` rules are unanchored regexes. The `modules/.*\.sops\.yaml$` rule already matches both `src/modules/...` and `modules/...`; only the two `src/kubernetes/clusters/...` rules encode the prefix.
- The repo is jujutsu-colocated with git. Work happens in a worktree that does not contain the untracked files above.

## Goals / Non-Goals

**Goals:**

- One atomic commit that moves the trees and rewrites every tracked path reference, so any checkout of that commit is self-consistent for Nix, `just`, pre-commit, sops, and Zed.
- A documented, ordered cutover for the two things git cannot carry: OpenTofu local state and the live `FluxInstance` sync path.
- Zero semantic change: same flake outputs, same Flux objects, same tofu plan.

**Non-Goals:**

- Finishing the work-in-progress `bootstrap/kubernetes/` seed manifests or making the Kubernetes server aspect evaluate. The change moves the directory, updates the Nix references to `bootstrap/...`, and updates the sync path in `flux-instance.yaml` if that file exists on disk; it does not author missing files.
- Renaming anything _inside_ the trees (file names, aspect names, the `terraform` RouterOS user and its `terraform-password` sops keys, the `terraform` treefmt-nix program block).
- The `paths:` globs in `.claude/rules/*.md`. They reference trees that do not exist and are being replaced by a new rule set in separate work. Also out of scope: the `.github/workflows/flux-local.yaml` `flux/cluster` paths, a pre-existing mismatch.
- Touching untracked docs in the main checkout (`AGENTS.md`, `docs/`, `plans/`).
- Moving `src/homelab/` or changing the Python packaging.

## Decisions

**D1. Move with `jj`/`git mv` in a single change, then rewrite references with a scripted search-and-replace and review the diff.**
Alternatives: (a) hand-edit each of the ~100 references; (b) shim the old paths with symlinks from `src/kubernetes` to the new `kubernetes/` and migrate lazily. (a) is error-prone at this count and gives no advantage. (b) keeps two spellings alive, breaks `import-tree` (it would traverse the symlink and double-import), and Flux would still need the real path. A scripted rewrite of the exact strings `src/kubernetes`, `src/modules`, `src/terraform`, `src/mikrotik`, `src/bootstrap`, `src/topology.yaml`, and `./src/` is mechanical and its diff is reviewable. The rewrite must skip `src/homelab`, `vendor/`, `uv.lock`, `flake.lock`, and the `_ai-tools` skill/command markdown whose `src/` mentions are generic examples.

**D2. Rename `terraform` to `tofu` at the directory level only.**
The RouterOS `terraform` user/group, the `terraform-password` sops keys, the `terraform {}` HCL blocks, and the `terraform` treefmt-nix program name are all identifiers with external meaning (router accounts, encrypted keys, provider protocol, upstream option name). Renaming them is a separate change with its own blast radius. The directory name is the only thing that is purely cosmetic.

**D3. Regenerate `flake.nix`; never edit it.**
Change `flake-file.outputs` in `modules/inputs.nix` to `import-tree ./modules`, then `just regen`. The header of `flake.nix` says so, and a hand edit would be overwritten on the next regen anyway.

**D4. Fix the symlinks by recreating them, not by moving them.**
Both trees move up one level, so links that pointed at the repo root through `src/` lose one hop, while links between siblings that both moved keep their depth:

- `tofu/secrets` must point one directory up (it pointed two up).
- `tofu/topology.yaml` keeps pointing one directory up, now at the root file.
- `mikrotik/bootstrap/secrets` must point two directories up (it pointed three up).
- `mikrotik/bootstrap/topology.yaml` keeps pointing two directories up.
  `git mv` preserves link targets verbatim, so the two that changed depth must be re-linked. Verify with `readlink` and by `sops -d` through the link.

**D5. Sequence the Flux cutover as merge, then sync-path change, relying on Flux's build-before-prune semantics.**
The sync path is cluster state and the directory it names is commit state, so there is no order in which both are correct at once. If the commit lands first, the root `flux-system` Kustomization looks for `src/kubernetes/clusters/<dc-domain>/flux` in the new artifact and fails. If the path is changed first, it looks for `kubernetes/clusters/...` in the old artifact and fails. Both clusters hit this at the same moment because both sync the same repository.

That failure is safe. Flux prunes only after a successful build and apply: it renders the directory, diffs the resulting object set against the inventory from the last successful apply, and garbage-collects the difference. A "path not found" error aborts before rendering, so the inventory is untouched and nothing is deleted. The child Kustomizations and every HelmRelease keep their last applied state; helm-controller does not uninstall a release because its source went stale. Workloads never notice. The window is a stall, not an outage.

The one way this could break a cluster is a _successful_ render of the new path that yields different object names. `flux-system` has `prune` on and its inventory is `cluster-config` and `cluster-apps`; if either were renamed, Flux would prune the old object, and since those carry `prune: true` themselves the deletion would cascade through every app. The invariant to protect is therefore: move the `flux/` directory intact, keep both file names and `metadata.name` values, and do not add a `kustomization.yaml` beside them (it would shadow the two files and render an empty set, which is the same cascade). Task 8.5 checks this before touching the path.

Chosen order: merge, then update `spec.sync.path` on both `FluxInstance` objects to `kubernetes/clusters/<dc-domain>/flux`, then `flux reconcile source git flux-system` and watch both roots return to Ready. Merge-first keeps git as the source of truth before any cluster state changes. Optionally suspend `cluster-config` and `cluster-apps` on both clusters before merging and resume after the path change; this removes the error noise in the window but is not required for safety.

How the path gets applied: the `FluxInstance` is delivered by k3s from its auto-deploy `manifests` directory, rendered from `bootstrap/kubernetes/flux-instance.yaml` by `kubernetes.nix`. That file is work in progress and not yet in the repo. The GitOps-correct route is to set the new path in that file and rebuild the server nodes, which re-applies the manifest. Until the file is real, `kubectl patch` on the live object is the fallback. Either way the file must carry the new path once it exists, because a later rebuild would otherwise re-apply the old `src/...` value and re-freeze Flux.

**D6. Tofu state moves by hand in the main checkout, before the first `tofu` command in the new directory.**
Local backend, no `backend {}` block. Moving `terraform.tfstate`, its backups, `.terraform/`, `authentik.auto.tfvars.json`, and `.scratch/` into `tofu/` is a plain `mv`; the lock file `.terraform.lock.hcl` is tracked and moves with git. Verification is `tofu plan` showing no changes. Alternative: `tofu init -migrate-state` is for backend changes, not directory moves, and is unnecessary here.
`da.cloudflare-tunnel.tofu` is untracked-but-not-ignored in the main checkout; it must be moved (or committed) alongside, or the `cloudflare-tunnel` external-secret comment that cites it will point at nothing.

**D7. Treat `src/bootstrap` as part of the flatten even though it is untracked.**
The user's request is "`src/*` become root-level". `talos.nix` and `kubernetes.nix` both hard-code the path, so leaving the directory under `src/` would keep a `src/` reference in Nix. Move the on-disk `talos/machineconfig.yaml` to `bootstrap/talos/` in the main checkout and update both modules to `<self>/bootstrap/...`. Whether `bootstrap/` should become tracked is left to the user; it is not required for this change.

**D8. Rewrite doc headings and comments in the same commit.**
AGENTS.md files under `modules/`, `kubernetes/`, `kubernetes/clusters/`, `modules/secrets/`, `modules/services/kubernetes/`, plus comments in `zerotier.nix`, `wg-holonet.nix`, `inputs.nix`, `kubernetes.nix`, `da-gr75.nix`, `users.tofu`, `ak.variables.tofu`, the `cloudflare-tunnel` external-secret, and `recyclarr.yml`. Two are already wrong today and get corrected as a side effect: `users.tofu` cites `src/mikrotik/justfile` (actual: `mikrotik/bootstrap/justfile`) and `wg-holonet.nix` cites `src/topology/holonet.yaml` (actual: `topology.yaml`). `kubernetes/clusters/AGENTS.md` already says `modules/services/kubernetes/kubernetes.nix` without the prefix and needs no change.

## Risks / Trade-offs

- [Both clusters stall between merge and sync-path change] → Expected and harmless (see D5); do the path change immediately after merge in the same sitting, or suspend the two root Kustomizations on both clusters beforehand and resume after. Confirm with `flux get kustomizations -A` that both roots return to Ready on the new revision.
- [Cascading prune if the root render changes shape] → Move `flux/` intact; before changing the path, verify both clusters' `flux/` directories still contain exactly `cluster-config.ks.yaml` and `cluster-apps.ks.yaml` with unchanged `metadata.name`, and no `kustomization.yaml`.
- [Wrong or partial `FluxInstance` path assumption] → Read the live object first (`kubectl get fluxinstance -n flux-system -o yaml`) rather than trusting `AGENTS.md`; the design assumes `src/kubernetes/clusters/<dc-domain>/flux`.
- [A later server rebuild re-applies the old sync path] → Set the new path in `bootstrap/kubernetes/flux-instance.yaml` as part of the cutover if the file exists on disk; if it does not exist yet, record in the commit body that it must carry `kubernetes/clusters/${dc-domain}/flux` when written.
- [Scripted rewrite touches a string it should not] → Restrict the rewrite to the exact prefixes listed in D1, exclude the paths listed there, and review `jj diff --stat` plus a grep for any remaining `src/` that is not `src/homelab`. The `_ai-tools/**` markdown examples (`src/auth/login.ts`, `src/api/...`) are generic and must survive.
- [Tofu state left behind in `src/terraform/`] → The first `tofu plan` in `tofu/` would show every resource as "to be created". Make the state move the first tofu task and gate on a clean plan before anything else tofu-related.
- [`nix flake check` cannot be a full gate] → The kubernetes server aspect already fails to evaluate (missing `bootstrap/kubernetes`). Gate on the outputs that evaluate today: `nix flake show`, `nix eval .#nixosConfigurations.<host>.config.system.build.toplevel.drvPath` for a host without the server aspect (`da-gr75`, `da-n1x`), the darwin host, `nix build .#checks.<system>.den-tests`, and `nix develop --command true`. Record which hosts were checked.
- [Worktree vs main checkout split] → The tracked changes land via the worktree; the untracked moves (state, `bootstrap/`, `da.cloudflare-tunnel.tofu`, `.direnv` re-allow) happen in the main checkout after it picks up the change. Tasks call out which side each step runs on.
- [`just` module cwd semantics] → `mikrotik.just` uses `justfile_directory()/secrets/hosts/...`; verify after the move that `just mikrotik list-interfaces <target>` still finds the sops file, since `justfile_directory()` inside a module may resolve to the module's own directory (which would also work via the `tofu/secrets` symlink).
- [Rollback] → Before the `FluxInstance` patch, rollback is `jj abandon`/revert of the single commit. After the patch, rollback is revert plus re-patching the sync path back; state files move back with a plain `mv`.

## Open Questions

- When `bootstrap/kubernetes/` graduates from work in progress, should it become tracked so the `FluxInstance` sync path is versioned with the manifests it points at? Does not affect this change's tasks.
- Should the `.github/workflows/flux-local.yaml` `--path` arguments be fixed to `kubernetes/clusters/<dc-domain>/flux` in a follow-up? The filter pattern `kubernetes/**/*` becomes correct with this change; the `--path` values were wrong before and remain wrong.
